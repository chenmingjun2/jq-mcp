# jq-mcp：让你的 AI Agent 直接操作聚宽（开源）

> 仓库：https://github.com/chenmingjun2/jq-mcp
> 定位：**给 AI Agent 用的聚宽操作与回测编排层**，权限全程留在浏览器里。

---

## 一、为什么做这个

现在用 AI 写策略、改代码已经很顺，但真正的瓶颈在“落地”：

- 改完代码，还得手动**粘贴到聚宽编辑器**；
- 每次回测要**点参数、提交、等结果、翻指标**；
- 想做**参数消融/多标的对比**，就得几十次重复劳动；
- 想把回测数据拿给 AI 分析，又得手动复制。

**jq-mcp 就是来消除这段机械劳动的**：把聚宽的“策略管理 / 编译 / 回测 / 数据读取”变成 AI 能调用的工具，让 Agent 自己完成“生成 → 编译校验 → 回测 → 取数 → 迭代”的闭环。

---

## 二、它是什么（以及不是什么）

**是**：
- 一套 **MCP 工具**（40 个），把网页里能做的事暴露给 AI Agent；
- 一个**浏览器插件（jqhelper）**，持有你的登录态，在页面里完成真实操作；
- 一个 **Go 写的本地服务器**，只做指令转发、任务登记与本地文件。

**不是**：
- 不是行情/因子数据源；
- 不是托管平台；
- 不托管账号密码、不绕过登录与风控；
- 不做投资建议或自动下单。

---

## 三、它是怎么工作的（关键设计）

```text
AI Agent ──MCP──▶ jq-mcp(Go，本地) ──WebSocket──▶ jqhelper(浏览器插件) ──同源请求──▶ joinquant.com
```

- **服务端从不直连聚宽私有接口**；所有操作都由**已登录的浏览器**发起。
- 登录完全由你**手动完成**；jq-mcp 不接触你的账号密码，也不保存 Cookie。
- 服务端只监听 `127.0.0.1`，用一把随机 token 与本机插件通信。

**为什么锁在浏览器里？**
账号密码与会话不离开浏览器、免逆向认证、请求更像真人、站点改版时只需改插件——安全、稳、可维护。

---

## 四、和 jq-cli 有什么不同？（重点）

两者都能操作聚宽，但**定位与信任模型完全不同**：

- **jq-cli**：面向**人**的命令行工具，**服务端直连**聚宽私有接口，凭据（账号密码 / token / cookie）存在本地配置里。
- **jq-mcp**：面向 **AI Agent** 的 MCP 能力层，操作**在浏览器里**完成，服务端**零凭据**。

| 维度 | jq-cli | jq-mcp |
|---|---|---|
| 定位 | 人用的命令行工具 | AI Agent 用的 MCP 工具层 |
| 语言 / 分发 | Python 包 | Go 单二进制 + 零构建 MV3 插件 |
| 认证 | 账号密码登录，或 token/cookie 存本地配置 | **浏览器手动登录**，服务端不接触密码/Cookie |
| 请求路径 | 服务端 httpx **直连**私有接口 | **页面同源请求**（浏览器内发起），服务端不直连 |
| 风控观感 | 服务端脚本直连，较易被识别 | 真实浏览器指纹、像站点自己的前端在请求 |
| 运行依赖 | 纯 CLI，可无人值守 / 跑在服务器 | **需要已登录的浏览器**（attach / launch） |
| 能力面 | 更广：auth/strategy/backtest + **community / research(Jupyter) / simulation** | 聚焦**策略 + 编译 + 回测 + 数据**；额外有编译校验、成交/持仓/月度、账号上限、`confirm`、任务登记 |
| 批量 / 编排 | 自己写 shell / Python 循环 | 由 **AI Agent 编排**（也可脚本调同一套 MCP 工具） |
| 安全模型 | 凭据与源码保存在本地配置，服务端持有 | 凭据**不落库**、破坏性操作需 `confirm`、仅本地 token |
| 是否依赖浏览器 | 否 | **是（核心设计）** |
| 面向的“消费者” | 人（终端） | AI Agent / 脚本 / CLI 均可 |

**一句话区别**：
> jq-cli 是“**人直连聚宽**的命令行”；jq-mcp 是“**让 AI 以一个真实的、已登录的浏览器身份**去操作聚宽”。

**怎么选**
- 要**无人值守、跑在服务器**，或需要 **research(Jupyter) / simulation / community** → jq-cli 更合适。
- 要**接入 AI、凭据不外泄、以真实浏览器身份操作、要 Agent 编排回测闭环** → jq-mcp 更合适。

> 说明：本项目是**独立实现**（Go + MV3 插件），仅在功能点上做了参考，**未复用 jq-cli 的代码**。

## 五、能做什么（40 个工具）

- **认证**：登录状态、打开登录页、刷新会话；读取 Cookie（敏感，按需）。
- **策略**：列表/查找/读取源码、新建、保存、复制、删除；文件夹管理。
- **编译/回测**：**先编译校验再回测**、发起回测（正式/编译运行）、批量提交、指标对比、取消、删除。
- **回测数据**：详情、收益/风险指标、收益曲线、日志、**成交明细、每日持仓、月度收益**、导出到本地。
- **本地**：源码导入/导出、滑点/手续费标准化注入、文件读写。
- **账号**：并行回测/编译上限探测。

只读操作直接调用；**删除/覆盖类操作需显式 `confirm`**。

## 六、三步用起来

```bash
# 1) 构建（需要 Go 1.24+）
git clone https://github.com/chenmingjun2/jq-mcp
cd jq-mcp && make build

# 2) 启动服务（会生成 token）
bin/jq-mcp
```

3. 在 `chrome://extensions` 用“加载已解压的扩展程序”选择 `extension/` 目录，
   在插件选项页填入 `ws://127.0.0.1:8790/ws` 和 token；
   在浏览器登录聚宽；把 `bin/jq-mcp` 配进你的 MCP 客户端（OpenCode / Claude Desktop 等）。

验证：调用 `jq_health` 返回 `{"connected":true,"loggedIn":true}` 即可。
仓库自带 OpenCode skill（`.opencode/skills/jq-mcp`），AI 会自动按其中的工作流与注意事项使用。

## 七、实战示例：给“永久投资组合-黄金股票能源”做消融

这个策略是 `美国50 + 华夏黄金 + 长江电力` 三等权 + ±10% 带宽再平衡。我们用 jq-mcp 自动跑了 **37 次回测**（短/长窗口 + 单腿/去一腿/换标的/加腿），几个关键结果：

**短窗口（2023-12 ~ 2026-09）**

| 变体 | 年化 | 回撤 | Sharpe |
|---|---|---|---|
| 基准（三等权） | 24.2% | 12.0% | 1.52 |
| 仅美国50 | 26.5% | 28.7% | 0.85 |
| 仅黄金 | 25.9% | 30.3% | 1.02 |
| 仅长江电力 | 11.3% | 15.2% | 0.51 |

**长窗口（2014-01 ~ 2026-09）**

| 变体 | 年化 | 回撤 | Sharpe |
|---|---|---|---|
| 基准（纳指+黄金+长江） | 16.6% | 14.1% | 1.11 |
| 仅黄金 | 10.9% | 30.5% | 0.46 |
| 仅长江电力 | 15.8% | 22.0% | 0.64 |

**结论（AI 自动跑出来的）**：
- 组合把单腿 28–30% 的回撤压到 **12–14%**，**分散+再平衡**是真正的功劳；
- 但**强弱会反转**：黄金在近 2 年是明星，长周期却是最弱腿；长江电力相反；
- 两条“特色腿”（美国50 2023-11 上市、华夏黄金 2020-06 上市）**都是新标的**，历史上还被换成近期赢家——**后视镜明显**；
- **稳健的改进只有“加防守腿（国债/货币）降回撤”**，而不是“换标的提收益”。

> 这正是 jq-mcp 的典型用法：**AI 负责设计与判断，工具负责把几十次机械回测自动跑完。**

## 八、亮点小结

- **安全**：账号密码不出现、Cookie 不落库、`confirm` 门禁、敏感输出不打印。
- **高效**：走站点前端接口（页面同源请求），批量回测约 16 秒/条。
- **可编排**：MCP 工具，AI、脚本、CLI 都能调；自带 skill。
- **实用**：编译校验、成交/持仓/月度、批量、导出、并发上限处理。
- **开源**：MIT，Go + 零构建的 MV3 插件，跨 Linux/macOS/Windows（浏览器限 Chrome/Edge）。

---

## 九、已知限制

- 依赖聚宽**站点自己的前端接口**，站点改版需跟进维护；
- **需要浏览器在线**并保持登录；不是无人值守后台服务；
- 受账号**权益**约束（并行回测数、积分）；
- 仅适用于**本人账号、研究用途**，不绕过登录与风控。

---

## 十、适合谁

- 用量化做**策略迭代**、想把这套“建策略→回测→取数”的重复劳动交给 AI 的人；
- 需要**批量回测/消融/多标的对比**的人；
- 想在自己的 AI 工作流里接入**真实、已登录的聚宽账号**的人。

## 不适合谁

- 需要**无人值守、脱离浏览器**跑大批量的场景；
- 只想拿**行情/因子数据**（那是 JQData 的领域）。
